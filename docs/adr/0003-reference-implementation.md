# 0003 — A Python reference implementation before the Rust core

Status: accepted · 2026-11-06

## Context

The spec names a Rust core (`wl-core`) as the single implementation of the schema, the interval algebra and the metrics, precisely so that four platforms cannot drift apart.

M0's acceptance criteria were: golden-file tests pass, the facts document validates, and the determinism test is green. Those criteria are about *behaviour*, not about a language. The environment this work started in had no Rust toolchain and no route to install one (`static.rust-lang.org` unreachable), which made the literal M0 unbuildable and unverifiable there.

## Decision

Build M0 in two separable halves:

1. **The contract** — event format, metric definitions, fixture corpus, golden facts. Language-neutral, committed, versioned.
2. **An oracle** — `oracle/wl_oracle`, a Python implementation of the same arithmetic, tested against hand-computed expectations, producing the golden files.

The Rust core is validated against the same fixtures and the same goldens. Where the two disagree, the disagreement is a bug in one of them and must be resolved explicitly.

## Consequences

- M0's behaviour is verified now, by 35 tests, without a Rust toolchain.
- The golden files are generated by the oracle, so they are regression anchors rather than independent ground truth. The independent check is the hand-computed expectations in `test_metrics.py`; every golden change must be justified against one of them.
- Some duplication is permanent: the metric engine exists twice. That is the intended cost of differential testing, and it is cheaper than four implementations drifting.
- If the Rust port never happens, the oracle is still a working engine and the fixtures are still the contract — the project is not blocked on a rewrite.
